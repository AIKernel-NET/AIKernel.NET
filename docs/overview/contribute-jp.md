# 開発・ドキュメント改善に参加する

実行できない手順を知らせる、分かりにくい説明を直す、小さな不具合を修正する。AIKernelには、コードの追加以外にも参加方法があります。

## 問題を報告する

[GitHubのAIKernel-NET](https://github.com/AIKernel-NET)から、問題が起きたパッケージや機能のリポジトリを開き、既存のIssueを確認します。判断が難しい場合は[お問い合わせ](/contact/)から、対象のページやパッケージ名をお知らせください。

報告には、OS、SDKとパッケージの版、実行したコマンド、期待した結果、実際の結果と最初のエラーを添えます。ログからAPIキーと個人情報を取り除いてください。セキュリティに関する非公開の報告はメールを利用します。

## ドキュメントを訂正する

このサイトのガイドは、AIKernel.NETリポジトリの `docs/` にあるMarkdownから生成しています。誤りのあるページと原稿を対応づけ、準備・手順・期待する結果が読者に伝わるよう修正します。日英の対応ページがある場合は、両方の説明を揃えます。

実行例を変えたら、使用した版、確認環境、得られた出力を記録してください。確認できなかった部分は、その範囲を明記します。原稿には[ドキュメントの編集手順](../guidelines/DOCS_CONTRIBUTING-jp.md)も適用されます。

## コード変更を提案する

一つのPRでは一つの目的を扱います。公開インターフェース、契約、DTOの変更はIssueで追跡し、互換性が変わる場合は影響と移行方法を説明します。公開APIの説明は日本語と英語を揃えます。

対象リポジトリのREADMEとCI設定に従って、変更に関係するビルドとテストを実行します。PRには「どの問題が、どう変わるか」と検証結果を記載してください。AIによる執筆補助を使った場合も、内容をレビューして正しさを確認します。

## 詳細なルールを確認する

[Contributing Guide](../CONTRIBUTING-jp.md)にPRと検証の手順があります。[詳細な設計・開発ガイドライン](../guidelines/AIKERNEL_DEVELOPMENT_GUIDELINES-jp.md)は、公開インターフェースや実行の責務を変更するときに参照してください。この資料の「0.1.0」はガイドライン自体の版であり、現在のパッケージのインストール版を示すものではありません。
