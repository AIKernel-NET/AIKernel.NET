# AIKernel v0.1.3 GPU 正典 Migration Notes

AIKernel v0.1.3 では、AIKernel.Doom で実証した GPU work を正典 contract へ昇格します。
目的はすべての package を GPU 依存にすることではありません。WebGPU、Dawn、CUDA、
CPU fallback provider が同じ語彙で状態を報告できるようにすることです。

## 変更点

- `AIKernel.Enums` に `GpuBackend`、`GpuProviderCapabilities`、
  `GpuFrameTargetKind`、`GpuReadbackPolicy`、`GpuEgoRadarMode` を追加。
- `AIKernel.Dtos.Gpu` に frame token、raw/HUD frame target、frame diagnostics、
  GPU HUD input、GPU Aisthesis input/output、GPU spatial reasoning input/output の
  正典 DTO を追加。
- `AIKernel.Abstractions.Gpu` に provider、context、Aisthesis、Spatial Reasoner、
  HUD Composer、buffer、texture interface を追加。
- `AIKernel.Dtos.Gpu.GpuCanonicalValidation` に layout、capability、raw-frame capture、
  HUD buffer、spatial matrix、frame diagnostics、canonical diagnostics metadata dictionary の
  共有 validation を追加。
- GPU HUD state を geometry/style (`HudPanelRect`) と semantic state
  (`HudPanelStateVector`) に分離。
- Spatial reasoning は `AisMatrix` order で Topos、Route、Threat、Zoe の 9x9 matrix
  を 4 枚だけ受け取る。CTG やその他 task state は `StateVector` に置く。
- sensor analysis は `GpuFrameTargetKind.RawFramebuffer` を使う。HUD composite と
  display fallback target は presentation surface であり、Aisthesis input ではない。

## Provider Guidance

provider は、古い compute contract を併用する場合でも metadata に
`GpuProviderCapabilities` を公開します。Browser WebGPU provider は通常、次を設定します。

- `SupportsCompute`
- `SupportsHudComposite`
- `SupportsAisthesis`
- `SupportsSpatialReasoning`
- `SupportsZeroCopyRawTexture`
- `SupportsCpuFallback`
- `SupportsFrameDiagnostics`

Native CUDA capability module は通常、次を設定します。

- `SupportsCompute`
- `SupportsNativeValidation`
- `SupportsFrameDiagnostics`

Browser WebGPU provider は、初期実装が deterministic fallback projection を使う場合でも、
正典 pass interface を実装します。

- `IGpuProvider`
- `IGpuAisthesisProcessor`
- `IGpuSpatialReasoner`
- `IGpuHudComposer`

provider は 4 つの public path すべてについて `GpuFrameDiagnostics` を報告します。

- `GamePath`
- `BonsaiPath`
- `HudPath`
- `SensorPath`

zero-copy が利用できない場合、その path には fallback reason が必要です。同じ path で
`ZeroCopy=true` と `Readback=RequiredFallback` を同時に報告してはいけません。

bridge metadata は display-only data ではなく contract です。provider と browser/native
bridge adapter は、queue submission または JS/native handoff の前に、各 canonical diagnostics
metadata dictionary を `GpuCanonicalValidation.ValidateDiagnosticsMetadata(...)` で検証します。
boolean、integer、execution-mode、pilot-state、promotion-gate、pass-readiness value が不正な場合は、
下流で補正せず bridge boundary で fail closed します。

## Runtime Guidance

GPU shader code は、runtime layer で解決済みの状態に対する pure view にします。
Compass/radar smoothing、hold、decay、semantic suppression は、GPU buffer へ upload する前に
runtime layer で計算します。

## ブラウザーブリッジのアセット

`AIKernel.Wasm.WebGpuComputeProvider` が同梱する次のファイルを一式で使います。

- `runtime/browser/webgpu-envelope-bridge.js`
- `shaders/aisthesis/aisthesis.wgsl`、`shaders/spatial/spatial-reasoning.wgsl`、
  `shaders/hud/hud-composite.wgsl`
- `buffers/layouts/gpu-layouts.json`

ホストのコピー手順とブラウザーの import から旧 `rev3` パスを置き換えます。
別ビルドのブリッジ・シェーダー・レイアウトを混在させないでください。
ディスパッチのスキーマは `aikernel.gpu.dispatch`、エンベロープの版は
`0.1.3` で、NuGet の開発版サフィックスは付きません。ブラウザーでの
ディスパッチと決定論的な CPU フォールバックの両方を確認します。

## Developer Checklist

1. 依存パッケージを同じ `0.1.3` 系列に揃え、安定版と開発版を混在させない。
2. consumer package が v0.1.3 へ移行するとき、Doom-local future GPU DTO を
   `AIKernel.Dtos.Gpu` DTO に置き換える。
3. raw sensor capture は `RawFramebuffer` 経由にする。
4. HUD/composite target と Aisthesis capture を分離する。
5. `aik gpu verify` で layout を検証する。
6. higher-level host が restart boundary を所有しない限り、GPU lost は one-way CPU fallback として扱う。
7. shader pass binding 前に `GpuCanonicalValidation` で provider capability を検証する。
8. image analysis pass の前に `GpuAisthesisInput` を検証する。HUD-composited target は fail closed する。
9. matrix dispatch 前に `GpuSpatialReasoningInput` を検証する。Topos、Route、Threat、Zoe の順で
   9x9 matrix が 4 枚だけ必要。
10. browser JS、Dawn、CUDA bridge handoff 前に各 canonical diagnostics metadata dictionary を検証する。
11. HUD/log surface に `GpuFrameDiagnostics` を残し、browser demo が ad hoc flag なしで
    GPU / CPU fallback と zero-copy status を表示できるようにする。

## Doom Migration Notes

AIKernel.Doom は段階的に移行できます。

1. 現在の browser DTO adapter を compatibility shim として維持する。
2. raw capture descriptor を `GpuFrameTarget` に map する。
3. ego-radar/HUD state を `GpuHudInput` に map する。
4. Doom-local Aisthesis feature DTO を `GpuAisthesisInput` と `GpuAisthesisOutput` に置き換える。
5. Doom-local topology matrix を `GpuSpatialReasoningInput` に置き換える。
6. 既存 debug flag を削除する前に、Doom HUD status row と `GpuFrameDiagnostics` を比較する。

これにより public demo を安定させたまま、再利用可能な GPU vocabulary を AIKernel.Wasm と
AIKernel.NET へ移動できます。
