# 用語を具体例から調べる

読み進めていて分からない言葉が出たときのための用語集です。まず普通の言葉で役割を説明し、より詳しいページへつなげています。

| 用語 | 意味 | 読み方・具体例 |
| --- | --- | --- |
| Kernel | 実行の各部品をまとめる中心的な窓口 | 個々の接続処理をアプリの各所へ散らさずに扱う |
| Contract | 部品同士の型と呼び出し方の約束 | インターフェースやDTOを共通にする |
| DTO | 部品間でデータを受け渡す型 | 入力や結果を表すデータ |
| Provider | 外部機能を提供する実装 | モデル接続、ファイル、計算 |
| Capability | 利用できる処理として公開された機能 | 登録された処理を選んで呼び出す |
| Context | 実行に関わる入力や条件 | 参照情報、適用ルール |
| VFS | 保存方法を共通の窓口から扱うファイルの仕組み | メモリ上のファイルを読む実装 |
| ROM | 読み込み後に固定して扱う知識資産 | 実行が参照する知識のスナップショット |
| Operator | 処理の順序や結果の流れを管理する役割 | 前段の結果を確認して次へ進める |
| Observer | 実行を記録・監視する役割 | どこで何が起きたかの記録 |
| Replay | 記録した条件や結果を使う再現・検査 | Provider選択や入力の差を調べる |
| Fail-Closed | 条件を満たさない実行を先へ通さない扱い | 許可されなかった操作を拒否する |
| DAG | 循環のない有向グラフ | 処理同士の前後関係を表す |
| Wasm | WebAssemblyの略 | ブラウザーなどで実行するコード形式 |

## 名前だけでは動作は決まらない

Providerを追加しただけで、記録・再生・許可ルールがすべて設定されるわけではありません。使うホスト、登録、設定を合わせて確認します。「決定論的」という説明も、外部LLMの文章が必ず一致するという意味には読み替えません。

[概念の関係](../concepts/index-jp.md)を読むと、これらの言葉を一つのアプリの役割として理解できます。正確な型名やメンバーは[APIリファレンス](/reference-ja/)で確認してください。哲学由来の専門語や詳細な定義は、[設計・開発ガイドライン](../guidelines/AIKERNEL_DEVELOPMENT_GUIDELINES-jp.md)から参照できます。
